# @gamod/hanoi

[English](readme.md) | 日本語

ハノイの塔の局面を渡すと、目標の棒へ揃える最短手順の次の 1 手を返す。中身は探索ではなく**円盤を大きい順に 1 回なめるだけの攻略法 (O(n))**。決まった手順の何手目かを渡す形なら局面すら持たずに **O(1)** で返す。

> draft (`private: true`、未公開)。

## Install

```bash
pnpm add @gamod/hanoi
```

## Usage

```ts
import { bestMove, initialState, moveAt, movesLeft } from "@gamod/hanoi"

bestMove(initialState()) // => { disk: 0, from: 0, to: 2 } (3 枚を棒 0 から棒 2 へ)

// 途中の局面からでもよい。pegs[k] = 円盤 k (0 が最小) が乗っている棒
bestMove({ pegs: [1, 1, 0], target: 2 }) // => { disk: 2, from: 0, to: 2 }
movesLeft({ pegs: [1, 1, 0], target: 2 }) // => 4

// 棒 0 から棒 2 へ移す最短手順の step 手目 (1 始まり)
moveAt(3, 4) // => { disk: 2, from: 0, to: 2 }
```

## API

| export | 説明 |
| --- | --- |
| `bestMove(state)` | `{ disk, from, to }`: 最短手順の次の 1 手。全円盤が目標の棒にあれば `null`。O(n) |
| `movesLeft(state)` | 目標の棒に揃うまでの最短手数。O(n) |
| `moveAt(disks, step)` | `disks` 枚を棒 0 から棒 2 へ移す最短手順の `step` 手目 (`1..2^disks - 1`)。O(1) |
| `stateSchema` / `parseState` | zod schema と検証付きパーサ |
| `moveSchema` / `pegSchema` | 部品の zod schema |
| `initialState(disks = 3)` | `disks` 枚を棒 0 に積み、目標を棒 2 にした局面 |
| `MAX_DISKS` | 扱える最大枚数 (31) |

## 保証

**「最善」= 最短手順の次の 1 手。** ハノイの塔では、どの局面からでも目標の棒に揃える最短手順はただ 1 つに決まる。

- 1..8 枚・目標 3 通りの全局面 (29,520 局面) で、テスト専用の幅優先探索 (`reference/`) の最短手と一致することをテストしている。`movesLeft` も全局面で最短手数と一致する
- `moveAt` は 1..20 枚の手順を最後まで再生して規則違反が無く棒 2 に揃うこと、1..10 枚で `bestMove` と 1 手ずつ一致することをテストしている
- 幅優先探索の側も、初期局面から 2^n - 1 手であること、距離 d の局面がちょうど 2^popcount(d) 個あること (合計 3^n、最大距離 2^n - 1) で確かめている

## 攻略法

棒を 0, 1, 2 とし、円盤を大きい順に見て「その円盤を置くべき棒」t[k] を決める (一番大きい円盤は目標の棒)。

- 円盤 k が t[k] にあれば、小さい円盤も同じ棒を目指す
- 無ければ、小さい円盤を第 3 の棒へ逃がしてから k を動かすので、小さい円盤は第 3 の棒を目指す

この 2 つは `t[k-1] = -(t[k] + pegs[k]) mod 3` の 1 式にまとまる。目標に無い円盤のうち**最小のもの**を t[k] へ動かす手が最短手。最短手数は目標に無い円盤 k ごとの 2^k の和になる。

### moveAt が O(1) になる理由

初期局面からの最短手順に乗っている局面は、何手目か (n ビットの整数 1 個) で表せる。step 手目に動く円盤は step の最下位の立っているビット、棒は `(step & (step - 1)) % 3` から `((step | (step - 1)) + 1) % 3` へ (偶数枚なら棒 1 と 2 を入れ替える) で決まり、ループが要らない。局面 (`pegs`) を受け取る `bestMove` は、どの円盤の位置も答えに効くので全円盤を読む O(n) が下限になる。

## State

```ts
type State = {
  pegs: (0 | 1 | 2)[] // pegs[k] = 円盤 k (0 が最小) が乗っている棒。1..31 枚
  target?: 0 | 1 | 2 // 全円盤を集める棒。既定は 2
}

type Move = { disk: number; from: 0 | 1 | 2; to: 0 | 1 | 2 }
```

- 同じ棒の上では大きい円盤が必ず下になるので、棒の中の順番は持たない。この表し方では規則違反の積み方が書けない。
- どの並びも初期局面から到達できるので、到達不能として弾く局面は無い。形のおかしい state (円盤が無い、存在しない棒、31 枚超) は例外を投げる。
