# @gamod/yacht

[English](readme.md) | 日本語

世界のアソビ大全51 版ヨット (1 人プレイ) の局面を渡すと、**合計点の期待値が最大になる手** (振り直すサイコロ / 記入する役) を返す。

> **draft (private, 未公開)。** 手番内の最善手計算と、テスト専用の厳密な期待値 DP は完成している。
> 手番をまたぐ期待値テーブル `V` を**どの形で出荷するか**が未決のため、今は `V` を外から渡す API (`createBestMove`) になっている。
> 形式が決まったら共通規約どおり `bestMove(state)` を公開する。

## Install

```bash
pnpm add @gamod/yacht # 未公開 (draft)
```

## Usage

```ts
import { createBestMove, initialState } from "@gamod/yacht"

// valueFn: (記入済みの役の bit, 上段合計) => 手番開始時の期待値。出荷形式は未決
const bestMove = createBestMove(valueFn)

bestMove(initialState([6, 1, 6, 6, 6]))
// => { type: "reroll", keep: [0, 2, 3, 4] } (6 を 4 つ残して 1 を振り直す)

bestMove({ dice: [2, 3, 4, 5, 1], rerollsLeft: 0, sheet: { aces: 3 } })
// => { type: "score", category: "bigStraight" }
```

## API

| export | 説明 |
| --- | --- |
| `createBestMove(valueFn)` | 最善手を返す関数を作る。返り値は `{ type: "reroll", keep }` (残すサイコロの位置) か `{ type: "score", category }`。記入表が埋まっていれば `null` |
| `stateSchema` / `parseState` | zod schema と検証付きパーサ |
| `moveSchema` | 手の zod schema |
| `initialState(dice)` / `emptySheet` | 初期値 (出目は呼び出し側が振る) |
| `CATEGORIES` / `UPPER_BONUS` / `UPPER_BONUS_THRESHOLD` | 役の一覧とボーナスの定数 |

## 保証

**「最善」= 合計点の期待値が、最善を尽くした場合と一致する手。** 1 ゲームの点を最大化するのではなく、平均を最大化する (対戦相手の点は考慮しない)。

- 初手からの最適期待値が公開値 **191.77** と一致する (DP の値は 191.77437)
- 最終手番に 1 役だけ残った局面の期待値が、公開値 (エース 2.10648、チョイス 23.33333、フルハウス 7.01355、B.ストレート 7.83285、ヨット 2.30143) と一致する
- src とは独立に書いた素朴な検算役 (並び順付きの出目 7776 通りの総当たり) と、ボーナス境界を含む局面で DP の値が一致する
- 同じ検算役で、残り 2 役の局面の全出目 × 振り直し残り 0〜2 回について、選んだ手が最適期待値に達している

## 仕組み

- `V(記入済みの役, 上段合計)` = 手番開始時点の「これから取れる点」の期待値。上段合計は 63 で頭打ちにできるので、到達しうる局面は **178,816**。
- 手番の中 (振り直し 2 回) は、V から数 ms で計算する (`src/turn.ts`)。出目は並び順を区別しない多重集合 (保持 0〜5 個で 462 通り) に潰し、「1 個振るごとの平均」の繰り返しで期待値を出す。
- 出荷物はゲーム全体を探索しない。V を後ろ向きに全部解く DP は `reference/` (テスト専用、約 5 秒) にある。
- 条件分岐だけの攻略法 (tic-tac-toe の方式) にはできない。期待値が最適になる簡潔な戦略は知られていないため、V が削れない核になる。

## ルール

| 役 | 条件 | 点 |
| --- | --- | --- |
| エース〜シックス | — | その目の合計 |
| チョイス | — | 5 個の合計 |
| フォーダイス | 同じ目が 4 つ以上 | 5 個の合計 |
| フルハウス | 3 つ + 2 つ。**5 つ同じ目も含む** | 5 個の合計 |
| S.ストレート | 4 つ以上連続 | 15 |
| B.ストレート | 5 つ連続 | 30 |
| ヨット | 5 つ同じ目 | 50 |

上段 (エース〜シックス) の合計が 63 以上で +35。1 手番は最初の 1 回 + 振り直し 2 回。

5 つ同じ目がフルハウスに含まれることは、公開されている最終手番の期待値 7.01355 がこの解釈でだけ一致することで確かめた (含めない場合は 6.96573)。

## State

```ts
type State = {
  dice: number[] // 長さ 5、各 1..6
  rerollsLeft: 0 | 1 | 2 // この手番で残っている振り直しの回数
  sheet: Partial<Record<Category, number>> // 記入済みの役だけキーを持つ
}
```

**実戦で現れない局面は例外を投げる。** 条件は「記入済みの点がどれも、その役で実際に出せる点であること」だけ (例: エースに 6 点、チョイスに 4 点、S.ストレートに 30 点は弾く)。役は互いに独立に記入でき、上段合計はそこから決まるだけなので、これで到達可能な局面と一致する。

## 出荷形式の計測 (未決事項)

`pnpm --filter @gamod/yacht measure` で計測する。結果は `table/measure.md` に書かれる (`table/` は git 管理外)。サイズは整数化 → 上段合計方向の差分 → brotli の目安。損失は近似した表で手を選び続けたときの、初手からの期待値の差 (方策評価による厳密値)。

| 表現 | 値の数 | brotli | 損失 (点/ゲーム) |
| --- | ---: | ---: | ---: |
| 厳密表 float64 | 178,816 | 699 KB | 0 |
| 厳密表を 1/4096 点刻み | 178,816 | 213 KB | 2.4e-9 |
| 厳密表を 1/256 点刻み | 178,816 | 139 KB | 2.4e-6 |
| 厳密表を 1/16 点刻み | 178,816 | 90 KB | 4.2e-4 |
| 厳密表を 1 点刻み | 178,816 | 33 KB | 0.10 |
| 加法近似 L[下段, 上段の残り役数] + U[上段, 合計] | 3,242 | 2.6 KB | 0.51 |
| 加法近似 L[下段] + U[上段, 合計] | 2,858 | 2.1 KB | 0.97 |

上段合計の違いで値が変わらない局面 (ボーナスが確定している / もう届かない) を畳むと、厳密なまま値の数は 103,552 になる。
