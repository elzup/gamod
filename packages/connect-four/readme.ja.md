# @gamod/connect-four

[English](readme.md) | 日本語

コネクト4 (7 列 x 6 段) の局面を渡すと最善手 (どの列に落とすか) を返す。中身は**定石表 + 完全読み探索**。三目並べと違って簡潔な攻略法が存在しないゲームなので、このパッケージだけは出荷コードに探索を持つ。

## Install

```bash
pnpm add @gamod/connect-four
```

## Usage

```ts
import { bestMove, initialState } from "@gamod/connect-four"

bestMove(initialState()) // => 3 (中央。先手はここに置けば勝てる)

// 左上から右下へ 42 マス。空きは null、r が先手
bestMove({
  board: [
    ...Array(28).fill(null),
    null, null, null, "y", "y", "y", null,
    null, null, null, "r", "r", "r", null,
  ],
  turn: "r",
}) // => 2 (下段に 4 連が完成する)
```

| export | 説明 |

## 保証

**「最善」= 完全読みと同じ勝敗になる手。** 勝てる局面は勝ち切り、引分の局面は負けない。最短で勝つことは保証しない (勝ち筋を保ったまま遠回りすることがある)。

- 4x4 盤の全 161029 局面で、テスト専用の全探索 ([`reference/`](reference)) と勝敗・決着までの手数の両方が一致することを確認
- 5x4 / 4x5 / 7x6 の終盤局面 (乱数で抽出) でも同じく突き合わせ
- ルール実装そのものは、John Tromp が公開している ply ごとの局面数 (1, 7, 49, 238, 1120, 4263, 16422, 54859) と一致することを確認

## 中身

### 探索

Pascal Pons の Connect 4 solver と同じ組み立て。

1. **αβ 探索** + **置換表** (局面を (height + 1) bit x 列 のキーに詰める。左右反転は同一視)
2. **反復深化 + null window**: 「このスコア以上か」だけを判定して勝敗と決着の早さを詰める
3. コネクト4 固有の枝刈り
   - 自分が次の 1 手で 4 連を作れるならそこで打ち切る
   - 相手のリーチが 2 つあれば受け切れないので負け確定
   - 相手のリーチが 1 つならそこを埋めるしかない (合法手が 1 つに縮む)
   - 相手のリーチの真下には置かない (置いた瞬間に上を取られる)
4. **手順の並べ替え**: 新しくリーチを作る数が多い手から見る

### 定石表

序盤ほど読みが重いので、解析結果が公開されている初手だけ表で持つ。7x6 のコネクト4 は 1988 年に James D. Allen と Victor Allis が独立に解いていて、双方最善なら次のようになる。

| 初手 | 結果 |
| --- | --- |
| 中央 (col 3) | 先手勝ち (41 手目で決着) |
| その隣 (col 2, 4) | 引分 |
| 外側 4 列 (col 0, 1, 5, 6) | 後手勝ち |

表に入っているのはこの 8 局面 (左右反転を同一視して 5 キー) だけ。**一瞬で返るのは初期局面だけ**で、2 手目以降は表の外なので探索が答える (初期局面の最善手を決めるには初手 7 通りの値が要り、それがちょうど表にある)。表の値を自前の探索で検算するテストは 1 局面あたり数時間かかるので、`GAMOD_SLOW=1 pnpm test` のときだけ動く。

### かかる時間

置換表がまっさらな状態で `bestMove` 1 回にかかる時間 (Node.js v22, 乱数で作った局面):

| 盤上の石 | 時間 |
| --- | --- |
| 0 個 (初期局面) | 定石表が即答 |
| 20 個以上 | 1 ミリ秒未満 〜 数十ミリ秒 |
| 14 〜 18 個 | 数ミリ秒 〜 1 秒程度 |
| 12 個前後 | 数百ミリ秒 〜 数十秒 |
| 1 〜 10 個 | 数分 〜 数時間 |

置換表は最初に `bestMove` を呼んだときに 1 つだけ確保して以降使い回す (約 21MB)。同じ対局の続きを解くほど速くなる。

序盤の重さはコネクト4 の探索そのものの性質で、本家 (C++) でも同じ形の表になる。深い定石表を持てば埋められるが、12 手目までの表を作るには 1200 万局面を解く必要があるので、このパッケージには入れていない。

## state

```ts
type State = {
  board: ("r" | "y" | null)[] // 左上から右下へ 42 マス
  turn: "r" | "y"
}
```

`r` が先手。**実戦で現れない局面は例外を投げる** (黙って解くと嘘の最善手を返すため)。重力と着手順があるので、判定は次の 4 つ。左 4 列 x 下 4 段に収まる全局面を総当たりして、実際に辿れる局面と完全に一致することをテストで確認している。

- 石数と手番が合っている (r の手番なら同数、y の手番なら r が 1 個多い)
- 宙に浮いた石が無い
- 4 連は多くとも片方だけ。あるなら手番は相手側で、その 4 連を作った最後の 1 手を取り除ける形になっている
- 残りの石を下から順に、赤・黄と交互に置いていける並びが存在する
